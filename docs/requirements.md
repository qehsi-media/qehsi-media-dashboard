# qehsi-media-dashboard 需求文档与技术方案

- 项目名称：qehsi-media-dashboard
- 使用方：青岛实验高中国际部
- 文档版本：v0.1（第 0 步）
- 文档状态：待确认

---

## 1. 项目目标与非目标

### 1.1 项目目标

为青岛实验高中国际部搭建一个本地可运行的「新媒体数据看板」网页应用，统一查看 7 个宣传账号的数据表现，解决以下问题：

1. 7 个账号分散在抖音、视频号、公众号三个平台，数据割裂，无法横向对比。
2. 平台后台只能看单账号数据，缺少「本月整体宣传效果」的统一视图。
3. 缺少爆款内容识别、账号排名、IP 矩阵、多平台联动等分析视角。
4. 缺少面向学校管理层的服务价值小结与后期内容规划建议。

实现方式：**手动上传平台导出的 Excel/CSV 文件 → 系统自动解析入库 → 看板自动分析与展示**。

### 1.2 非目标（明确不做）

以下能力本期不实现，且后续版本也不计划实现：

1. 不实现任何自动登录、扫码登录、账号密码登录。
2. 不复用 Cookie、不做浏览器自动化（Selenium/Playwright 等）。
3. 不编写爬虫，不抓取抖音/视频号/公众号任何平台数据。
4. 不调用任何平台开放接口或第三方数据接口抓取数据。
5. 不做数据回写平台、不做自动发布内容。
6. 不做多用户权限体系、不做云端多租户（本期为本地单机应用）。
7. 不做实时数据（数据新鲜度取决于用户上传文件的频率）。

### 1.3 核心约束

1. 数据来源唯一：用户手动从平台后台导出的 Excel/CSV 文件。
2. 界面全部中文。
3. 每阶段结束后 `streamlit run app.py` 必须可运行。
4. 数据库字段名一旦确定，后续代码严格复用，不随意改名。
5. 分阶段开发，每阶段只做当前阶段范围内的功能。

## 3. 功能模块清单

本期共 8 个功能模块，对应看板中的 8 个页面/区块。

### 模块 1：数据上传与字段映射

- 上传 Excel（.xlsx/.xls）或 CSV 文件。
- 选择该文件对应的平台（`douyin` / `wechat_video` / `wechat_mp`）。
- 系统自动识别列名，展示「原始列名 → 标准字段」的映射界面，用户可手动调整。
- 支持预览前 N 行，确认无误后写入 SQLite。
- 支持查看历史导入记录（文件名、平台、导入时间、行数、成功/失败行数）。
- 平台导出文件的典型列名与标准字段需做内置别名匹配（例如「播放量」「播放次数」「视频播放量」均可映射到 `views`）。

### 模块 2：本月核心数据概览

- 可切换统计月份（默认当月）。
- 顶部指标卡：总内容数、总播放/阅读量、总点赞、总评论、总分享、总收藏。
- 分平台指标卡：抖音、视频号、公众号各自的内容数与核心量级。
- 环比上月变化（上月无数据时显示「无对比数据」）。
- 趋势小图：本月按日的内容发布量与播放/阅读量趋势。

### 模块 3：各账号表现排名

- 按月份 + 平台筛选。
- 排名榜（表格 + 条形图）：账号名称、内容数、播放/阅读量、点赞、评论、分享、收藏、互动率。
- 支持按不同指标切换排序。
- 支持「全部平台合并」与「分平台」两种视角。
- 互动率定义：`(点赞 + 评论 + 分享 + 收藏) / 播放或阅读量`，分母为 0 时显示 `—`。

### 模块 4：爆款识别（抖音爆款 / 视频号爆款 / 公众号爆款）

- 按平台分别识别爆款内容，不混排。
- 爆款判定规则（默认，可在界面说明中展示）：
  - 抖音爆款：本月该账号播放量 ≥ 该账号本月播放量中位数的 2 倍，或播放量进入全平台 Top 10%。
  - 视频号爆款：同上，基于播放量。
  - 公众号爆款：本月该账号阅读量 ≥ 该账号本月阅读量中位数的 2 倍，或阅读量进入全平台 Top 10%。
- 榜单展示：标题、账号、发布时间、播放/阅读量、点赞、评论、分享、收藏、链接、爆款原因说明。
- 当某平台数据不足（内容数 < 3）时，提示「数据量不足，爆款判定仅供参考」。

### 模块 5：IP 矩阵视图

- 展示 7 个账号的矩阵分布（按平台分组的三列卡片/矩阵表）。
- 每个账号显示：本月内容数、总播放/阅读量、平均互动量、最近一次发布时间。
- 标记账号活跃度：活跃 / 一般 / 停更（例如本月发布 0 条即「停更」）。
- 支持一眼看出「哪个平台投入多、哪个账号掉队」。

### 模块 6：多平台联动分析

- 同一主题/内容类型标签在不同平台的表现对比（例如某主题在抖音、视频号、公众号分别有几条、量级如何）。
- 展示「跨平台同题内容」表：主题标签相同的内容，按平台并列展示标题与数据。
- 平台贡献占比：各平台播放/阅读量占总量比例（饼图或堆叠条形图）。
- 发布节奏对比：各平台本月按周发布条数对比。

### 模块 7：服务价值小结

- 自动生成面向学校管理层的文字小结（模板化生成，非 AI 生成）：
  - 本月共产出内容 X 条，覆盖 3 个平台 7 个账号。
  - 总曝光 X，总互动 X，互动率 X%。
  - 表现最好的账号与内容。
  - 与上月对比结论（增长/持平/下降）。
- 支持一键复制小结文本（便于粘贴到汇报材料）。

### 模块 8：后期内容规划建议

- 基于数据的规则化建议（非 AI 生成）：
  - 爆款内容共性提炼（高频主题标签、高频内容类型）。
  - 低效账号/低效主题提示。
  - 建议加更的平台、建议调整的主题方向。
  - 下月内容选题建议条目（由规则模板生成，可人工编辑后导出）。
- 明确声明：建议由本地规则生成，仅供参考。

## 4. 数据字段设计建议

### 4.1 最终字段（数据库与代码统一使用，确定后不改名）

`accounts` 账号表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `account_id` | TEXT | 主键，如 `douyin_01` |
| `platform` | TEXT | 平台枚举：`douyin` / `wechat_video` / `wechat_mp` |
| `account_name` | TEXT | 账号名称，原样保存 |
| `account_group` | TEXT | 账号分组（同一品牌跨平台归组） |
| `status` | TEXT | 账号状态，默认 `active` |

`contents` 内容表：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | 系统生成 | 主键，自增 |
| `platform` | TEXT | 是 | 平台枚举 |
| `account_name` | TEXT | 是 | 账号名称，原样保存 |
| `content_title` | TEXT | 是 | 内容标题 |
| `publish_time` | TEXT | 是 | 发布时间，统一存为 `YYYY-MM-DD HH:MM:SS` |
| `views` | INTEGER | 是 | 播放量（抖音/视频号）或阅读量（公众号） |
| `likes` | INTEGER | 否 | 点赞数，缺省 0 |
| `comments` | INTEGER | 否 | 评论数，缺省 0 |
| `shares` | INTEGER | 否 | 分享/转发数，缺省 0 |
| `favorites` | INTEGER | 否 | 收藏数，缺省 0 |
| `link` | TEXT | 否 | 内容链接 |
| `content_type` | TEXT | 否 | 内容类型（如：短视频、图文、招生宣传、校园活动等） |
| `topic` | TEXT | 否 | 主题标签（如：招生、出分、校园生活、教师风采等） |
| `upload_batch` | INTEGER | 系统生成 | 上传批次 ID，关联 `upload_batches.id` |
| `created_at` | TEXT | 系统生成 | 入库时间 |

`field_mappings` 字段映射表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER | 主键，自增 |
| `platform` | TEXT | 平台枚举 |
| `source_column` | TEXT | 平台导出文件的原始列名 |
| `target_field` | TEXT | 对应的标准字段名 |
| `created_at` | TEXT | 创建时间 |

`upload_batches` 上传批次表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER | 主键，自增 |
| `platform` | TEXT | 该批次对应平台 |
| `file_name` | TEXT | 上传文件名 |
| `upload_time` | TEXT | 上传时间 |
| `row_count` | INTEGER | 该文件总行数 |
| `status` | TEXT | 批次状态（如 `pending` / `success` / `partial` / `failed`） |

`analysis_reports` 分析报告表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER | 主键，自增 |
| `report_month` | TEXT | 报告月份，`YYYY-MM` |
| `report_content` | TEXT | 报告正文 |
| `created_at` | TEXT | 生成时间 |

### 4.2 字段设计说明

1. 播放量与阅读量统一用 `views` 字段，通过 `platform` 区分语义；界面展示时按平台显示「播放量」或「阅读量」。
2. `publish_time` 统一转为字符串 `YYYY-MM-DD HH:MM:SS`，便于 SQLite 按月/按日分组统计。
3. 数值字段统一转为整数，空值或无法解析时按 0 处理；`content_title` 为空视为该行导入失败。
4. `content_type` 与 `topic` 允许为空，为空时界面显示「未标注」。
5. 去重策略：同一 `platform` + `account_name` + `content_title` + `publish_time` 视为同一条内容，重复导入时跳过并在导入结果中提示跳过行数。
6. 同一账号名称在不同平台下是不同账号，内容表以 `platform` + `account_name` 定位账号。

## 5. 各模块验收标准（可实际点击验证）

### 模块 1 验收标准

1. 打开看板，上传一个 CSV 文件并选择平台后，页面能显示原始列名与标准字段的映射下拉框。
2. 手动修改一个映射关系后，预览区对应列的数据随之变化。
3. 点击「确认导入」后，页面提示「成功导入 N 行，跳过 M 行，失败 K 行」。
4. 在「导入记录」中能看到刚才的文件名、平台、导入时间、行数。
5. 重复上传同一文件，页面提示跳过的重复行数，数据库记录数不增加。
6. 上传缺少必填列的文件时，页面明确提示缺少哪些字段，且不写入数据库。

### 模块 2 验收标准

1. 选择有数据的月份，顶部 6 个指标卡显示非零数值。
2. 切换月份后，所有指标卡与趋势图同步变化。
3. 选择无数据的月份时，页面显示「该月无数据」提示，不报错。
4. 环比区域在上月无数据时显示「无对比数据」，不显示错误数字。

### 模块 3 验收标准

1. 拉取排名表，行数等于该筛选条件下的账号数（最多 7 行）。
2. 切换排序指标，表格顺序与条形图顺序同步变化。
3. 切换平台筛选，只显示该平台账号。
4. 某账号播放量为 0 时，互动率显示「—」，不出现除零报错。

### 模块 4 验收标准

1. 抖音、视频号、公众号三个平台分别有独立的爆款区块，互不混排。
2. 每个爆款条目显示标题、账号、发布时间、播放/阅读量、互动数据、链接、爆款原因。
3. 点击或复制链接可打开对应内容页。
4. 某平台本月内容数少于 3 条时，该区块显示「数据量不足，爆款判定仅供参考」。

### 模块 5 验收标准

1. 矩阵视图同时显示 7 个账号，无遗漏。
2. 每个账号卡片显示内容数、播放/阅读量、平均互动量、最近发布时间、活跃度标签。
3. 本月发布 0 条的账号，活跃度显示「停更」。
4. 无数据的账号显示 0 或「暂无数据」，不出现空白卡片或报错。

### 模块 6 验收标准

1. 平台贡献占比图的三个平台比例之和为 100%（无数据平台显示 0%）。
2. 跨平台同题内容表能按 `topic` 把不同平台的同主题内容并列展示。
3. 发布节奏对比图按周显示三个平台的条数，周次与所选月份一致。
4. 无 `topic` 数据时，页面提示「暂无主题标签数据」，不报错。

### 模块 7 验收标准

1. 小结文本中包含内容总数、覆盖平台数、总曝光、总互动、互动率、最佳账号、最佳内容。
2. 切换月份后，小结文本同步更新。
3. 点击「复制小结」按钮，剪贴板得到完整文本。
4. 无数据月份时，小结显示「本月暂无数据，暂无法生成小结」。

### 模块 8 验收标准

1. 建议区显示「爆款共性」「低效提示」「建议方向」「下月选题建议」四块内容。
2. 建议内容随所选月份数据变化而变化。
3. 页面明确标注「建议由本地规则生成，仅供参考」。
4. 无数据月份时，页面提示「暂无足够数据生成建议」，不报错。

## 6. 项目文件结构（实际落地）

```
qehsi-media-dashboard/
├── app.py                     # 首页：项目名称、7 个账号、数据库状态
├── requirements.txt           # Python 依赖
├── pages/
│   ├── 01_数据上传.py         # 数据上传与字段映射（第 2 步）
│   ├── 02_数据看板.py         # 概览与账号排名（第 3 步）
│   ├── 03_爆款与矩阵.py       # 爆款识别与 IP 矩阵（第 4 步）
│   └── 04_月度报告.py         # 联动分析、小结、规划建议（第 5、6 步）
├── db/
│   ├── schema.sql             # 建表语句
│   ├── database.py            # 连接、初始化、账号同步
│   └── media_dashboard.db     # SQLite 数据库（自动生成）
├── config/
│   └── accounts.json          # 7 个账号清单
├── data/
│   └── uploads/               # 上传文件暂存目录
└── docs/
    └── requirements.md        # 本需求文档
```

约定：

- 每个页面文件对应一个模块组，统计逻辑后续按需拆到 `db/` 之外的工具模块中。
- `db/media_dashboard.db` 与 `data/uploads/` 下的文件不纳入版本管理。
- 所有页面统一从 `db/database.py` 取连接与账号信息，不各自建连接。

## 8. 已知限制（本期）

1. 数据依赖人工上传，无法做到实时更新。
2. 爆款判定使用中位数/分位数规则，账号数据量少时参考价值有限。
3. 服务价值小结与规划建议为规则模板生成，不具备语义理解能力。
4. 本期为本地单机应用，多人协作需自行部署。
5. 平台导出文件格式若发生变更，需要更新字段别名映射。
